# Phase 4: Social and Media Microservices - Complete

## Overview

Phase 4 completes the microservices extraction by separating Social and Media services into standalone FastAPI applications. SignRoad now runs as 5 independent services that communicate through an API Gateway.

## Services

### 1. Identity Service (Port 8001)
**Location:** `/home/ubuntu/repos/SR/identity-service/`

**Responsibilities:**
- User authentication (register, login)
- User management (profile, settings)
- JWT token generation and validation
- Admin user management

**Endpoints:**
- `POST /api/auth/register` - Register new user
- `POST /api/auth/login` - Login user
- `GET /api/auth/me` - Get current user
- `PUT /api/users/settings` - Update user settings
- `GET /api/admin/users` - Get all users (admin only)

### 2. Journey Service (Port 8002)
**Location:** `/home/ubuntu/repos/SR/journey-service/`

**Responsibilities:**
- Journey day content management
- User progress tracking
- Sign logging
- Journal entries

**Endpoints:**
- `GET /api/journey/days` - Get all journey days
- `GET /api/journey/days/{day_number}` - Get specific day
- `GET /api/journey/progress` - Get user progress
- `POST /api/journey/progress` - Update user progress
- `GET /api/journey/signs` - Get user signs
- `POST /api/journey/signs` - Log a sign
- `GET /api/journey/journal` - Get journal entries
- `POST /api/journey/journal` - Create journal entry
- `GET /api/journey/journal/{entry_id}` - Get specific entry
- `PUT /api/journey/journal/{entry_id}` - Update entry

### 3. Social Service (Port 8003) ✨ NEW
**Location:** `/home/ubuntu/repos/SR/social-service/`

**Responsibilities:**
- Cosmetics shop management
- Social features
- Community interactions

**Endpoints:**
- `GET /api/cosmetics` - Get all cosmetic items
- `POST /api/cosmetics/{item_id}/purchase` - Purchase cosmetic item

### 4. Media Service (Port 8004) ✨ NEW
**Location:** `/home/ubuntu/repos/SR/media-service/`

**Responsibilities:**
- Audio track management
- Media content delivery
- Subscription tier filtering

**Endpoints:**
- `GET /api/audio` - Get all audio tracks (filtered by subscription tier)

### 5. Main Backend (Port 8000)
**Location:** `/home/ubuntu/repos/SR/signroad-backend/`

**Responsibilities:**
- API Gateway (forwards requests to microservices)
- Admin panel endpoints (CRUD operations for all content)
- CORS configuration
- Request routing

## Key Features

### 1. API Gateway Pattern
The main backend acts as an API Gateway that:
- Forwards authentication requests to Identity Service
- Forwards journey requests to Journey Service
- Forwards social requests to Social Service
- Forwards media requests to Media Service
- Filters hop-by-hop HTTP headers
- Returns FastAPI Response objects for proper error handling

### 2. Shared Database Strategy
All services use the same PostgreSQL database (or in-memory storage for development):
- Consistent data model across services
- No data duplication
- Simplified deployment

### 3. JWT Token Validation
All services use identical JWT_SECRET_KEY for token validation:
- Tokens generated by Identity Service
- Validated by all other services
- Consistent authentication across services

### 4. Independent Deployment
Each service can be deployed independently:
- Separate Docker containers
- Separate Fly.io apps
- Independent scaling

## Environment Variables

All services require:
```bash
JWT_SECRET_KEY=<your-secret-key>  # Generate with: openssl rand -hex 32
DATABASE_URL=<postgres-url>        # Optional, uses in-memory storage if not set
ALLOWED_ORIGINS=<comma-separated>  # CORS origins
```

Gateway services also require:
```bash
IDENTITY_SERVICE_URL=http://localhost:8001
JOURNEY_SERVICE_URL=http://localhost:8002
SOCIAL_SERVICE_URL=http://localhost:8003
MEDIA_SERVICE_URL=http://localhost:8004
```

## Deployment to Fly.io

Each service has its own `fly.toml` configuration file.

### Deploy Identity Service
```bash
cd identity-service
fly apps create signroad-identity-service
fly secrets set JWT_SECRET_KEY=$(openssl rand -hex 32)
fly secrets set DATABASE_URL=<your-postgres-url>
fly deploy
```

### Deploy Journey Service
```bash
cd journey-service
fly apps create signroad-journey-service
fly secrets set JWT_SECRET_KEY=<same-as-identity>
fly secrets set DATABASE_URL=<your-postgres-url>
```

## Benefits of Phase 4

1. **Complete Separation of Concerns**
   - Each service has a single, well-defined responsibility
   - Social features isolated from journey features
   - Media content delivery separated from business logic

2. **Independent Scaling**
   - Scale Social Service during high shop traffic
   - Scale Media Service during peak audio streaming
   - Scale Journey Service during daily check-ins

3. **Easier Maintenance**
   - Smaller codebases per service
   - Clear boundaries between features
   - Easier to understand and modify

4. **Flexible Deployment**
   - Deploy services independently
   - Roll back individual services without affecting others
   - Test services in isolation

5. **Team Autonomy**
   - Different teams can own different services
   - Parallel development without conflicts
   - Clear API contracts between services
